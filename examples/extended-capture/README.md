# Authored extended-capture workflow

This reproducible example runs a small authored program through the real guest
CPU, captures more than 65,536 distinct identities, and compiles and executes the
complete result with the official consumer interfaces. It requires no commercial
game, firmware, checkpoint, private script or other project.

Build the headless toolkit first. From a committed, frozen toolkit checkout:

```powershell
python examples/extended-capture/workflow.py capture .local/my-extended-workflow --runner build/pce-headless.exe
python examples/extended-capture/workflow.py prepare .local/my-extended-workflow
python examples/extended-capture/workflow.py qualify .local/my-extended-workflow --generator Ninja
```

On other platforms select the corresponding `build/pce-headless` runner.
Choose a new output directory. CMake and the selected build tool/compiler must
be available. `qualify` accepts repeatable `--cmake-arg=-DNAME=value` options
forwarded to the official builder, for example explicit `CMAKE_CXX_COMPILER`
and `CMAKE_MAKE_PROGRAM` paths. Compilation of approximately 74,000 native sites
is an intentional standalone qualification, not a build repeated by every unit
test. Keep source and input pins unchanged between stages. Do not reuse output
directories or treat an interrupted stage as completed.

## The program and independent expectations

The generated input is exactly 8192 bytes loaded at physical `$1F0000`, with
logical PC `$4000`, all eight MPRs initially `$F8`, and A/X initially zero:

```text
offset 0           CSH
offset 1..8184     NOP
offset 8185        INX
offset 8186        TXA
offset 8187        TAM #$80
offset 8189        JMP $4000
```

The guest changes its otherwise-unused MPR7 on each round. Code remains in the
same physical work RAM, but complete source identity includes every MPR byte.
No instruction writes RAM. TAM's new mapping applies to the following JMP:
the initial MPR7=`$F8` context lacks that JMP, contexts 1 through 8 contain every
site, and context 9 contains only the final JMP. Thus the window has **ten full
MPR contexts and 73,701 distinct instruction identities**, without collapsing
identity to physical address or synthesizing captures from static enumeration.

Each round executes 8189 instructions and costs
`3 + 8184*2 + 2 + 2 + 5 + 4 = 16384` CPU cycles. Nine rounds end with these
literal expectations, counted from the authored program rather than copied
from a runtime result:

| Field | Expected |
| --- | --- |
| PC | `$4000` |
| A / X / Y | 9 / 9 / 0 |
| SP / P | 255 / 4 |
| MPR | `F8 F8 F8 F8 F8 F8 F8 09` |
| CPU cycles | 147456 |
| Master ticks | 442368 |
| Instructions retired | 73701 |

The explicit payload sandbox starts at the fast divider 3, so even the first
CSH is already fast: `147456*3 = 442368`. This initialization differs from
System Card reset, which starts at the slow divider.

## What each stage proves

`capture` runs the same window twice in the interpreter. Legacy capture retains
65,536 distinct identities and reports exactly 8165 dropped instructions, so it
is deliberately incomplete. The explicit extended profile with capacity 131072
retains all 73,701 identities, zero drops and zero unreadable instructions. The
helper checks every captured PC, full MPR map, physical address, opcode byte and
tier hit against the authored boundary plan. Raw stdout, stderr, commands,
process exit codes, input hashes and producer pins remain beside both captures.

`prepare` admits the original process evidence again, composes history format 2
at capacity 131072, and uses the supported `prepare_project` API to emit stable
translated C++ and a verified native-only descriptor. The history retains the
exact complete extended capture. The incomplete legacy capture remains separate
negative evidence and is never promoted into a lossless history. Preparation is
neither compilation nor native execution.

`qualify` invokes the official project builder and the official project runner.
It requires **73,701 actual native retirements, zero interpreter retirements and
zero guard misses**, with the same literal CPU endpoint and clocks. A new
extended capture from that native execution must contain every authored complete
identity with exactly one native hit. Official build/run receipts, build logs,
the official run command's stdout/stderr, and a separate qualification receipt
are retained. Failed process evidence is not replaced with a passing receipt.

The qualification receipt labels its payload digest as an **input identity**.
It does not measure final RAM and does not claim an all-RAM comparison. This
example qualifies extended capture, catalogue, emission and actual native
execution at the documented scale. It is internal compiler/runtime evidence,
not an independent emulator comparison or certification of a retail title.

Generated bytes, captures, histories, native source, binaries and receipts stay
in the ignored output directory. Only this authored recipe and its tests belong
in the public repository.
